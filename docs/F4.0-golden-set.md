# F4.0 — Golden Set + đo Precision/Recall (mutation testing UI)

> Spec sống. Chốt 2026-06-04. Mục tiêu: có tập ảnh/dữ liệu có nhãn lỗi sẵn để **đo
> precision/recall** của hệ thống và **tune ngưỡng** (F0.4). Tạo nhanh bằng **mutation
> testing**: inject lỗi đã biết → có ngay tập positive + giữ bản sạch làm negative.

## 0. Ràng buộc nền (QUAN TRỌNG)
- **Backend-agnostic — phải chạy với Cline.** Triển khai thật dùng **Cline** (máy công ty);
  **Codex** chỉ là backend test trên máy này. Vì vậy:
  - **Core golden + scoring = rule-only, deterministic, KHÔNG đụng agent backend nào.**
    `run_rule_engine(doc)` thuần tính toán → kết quả như nhau bất kể Cline/Codex/none.
    Đây là phần dùng để tune ngưỡng F0.4.
  - Đường reasoning (tùy chọn) đi **qua abstraction** `AGENT_BACKEND` (`agents/backends.py`:
    `run_backend` / `agents/runner.py`: `run_review`). **TUYỆT ĐỐI không import `codex_client`
    trực tiếp** trong script golden. Khi Cline cắm vào `backends.py` (nhánh `cline`), golden
    harness chạy y nguyên. Cờ CLI là **`--with-agent`** (không phải `--with-codex`).
- **Tier 1 trước (schema-level).** Tier 2 (ảnh thật Playwright) chỉ tạo thư mục + TODO,
  CHƯA build (OCR local chưa set up; xem F1.1/SETUP).

## 1. Catalog rule đích (tập tất định hiện có — 32 rule)
Golden label bám đúng các `rule` ID mà rule engine phát ra:
- **R1 geometry:** `R1-CMP01` (touch target), `R1-CMP16` (tap gap), `R1-ENV01/02/03` (safe-area),
  `R1-LAY01` (overlap siblings), `R1-LAY02` (offscreen), `R1-LAY03` (overflow container),
  `R1-LAY04` (lệch grid), `R1-LAY14` (near-dup position).
- **R2 color:** `R2-STY01..05`, `R2-STY13` (contrast / opacity / dark-mode).
- **R3 image:** `R3-IMG02` (méo aspect), `R3-IMG03`, `R3-IMG07`, `R3-IMG08`, `R3-IMG09`
  (scale-mode), `R3-IMG12`.
- **R4 text:** `R4-CNT01/02/04/05/06/07/08` (placeholder/undefined/i18n key/lorem/escape/
  mojibake/stacktrace/debug…), `R4-STATE03`, `R4-TYP03` (font nhỏ), `R4-TYP05` (truncation).

> Mỗi mutator NHẮM 1 rule trong danh sách trên. Agent A đọc trực tiếp `src/ui_defect/rules/*.py`
> để biết điều kiện kích hoạt + ngưỡng (F0.4) mà chế dữ liệu vượt ngưỡng vừa đủ.

## 2. Layout thư mục
```
data/golden/
  schema/                 # Tier 1 — làm ngay
    base/    <base>.json   # CanonicalDoc SẠCH (không lỗi), nguồn để mutate
    cases/   <case_id>.json   # CanonicalDoc đã mutate (INPUT cho rule engine)
    labels/  <case_id>.json   # ground truth (kỳ vọng)
  images/                 # Tier 2 — chỉ tạo dir + README TODO, CHƯA build
  report.md               # output của score (Agent B sinh, không commit number cứng)
scripts/
  gen_golden.py           # Agent A: sinh base → cases + labels
  score_golden.py         # Agent B: chấm điểm
tests/integration/
  test_golden.py          # Agent B: pytest baseline (CI chạy được)
```

## 3. Hợp đồng dữ liệu (interface giữa 2 agent — KHÓA CHẶT)
2 agent chạy song song độc lập nhờ thống nhất 2 schema sau. Không đổi field name nếu chưa báo.

### 3.1. `cases/<case_id>.json`
Là **đúng một `CanonicalDoc`** (Pydantic v2 — `src/ui_defect/schema/models.py`,
F0.2) đã được mutate, serialize bằng `model_dump(mode="json", exclude_none=True)`.
Phải load lại được bằng `CanonicalDoc.model_validate(json.load(...))`.

### 3.2. `labels/<case_id>.json`
```jsonc
{
  "case_id": "cmp01_tiny_button_v1",   // == tên file (không .json)
  "base": "mobile_login",              // base doc gốc
  "mutation": "shrink_touch_target",   // tên mutator
  "kind": "positive",                  // "positive" | "negative"
  "expected": [                        // [] BẮT BUỘC khi kind=negative
    {
      "rule": "R1-CMP01",              // rule ID phải kêu
      "element": "e7",                 // element id kỳ vọng (null nếu lỗi cấp screen)
      "severity_range": { "min": "medium", "max": "high" }  // 5 mức: critical|high|medium|low|trivial
    }
  ]
}
```
- **positive:** sau mutate, các rule trong `expected` PHẢI fire trên đúng element.
- **negative:** base sạch (hoặc biến thể vẫn hợp lệ) — rule engine fire bất kỳ issue nào = **FP**.
- Mỗi base SẠCH cũng được xuất thành 1 case `kind=negative` (đo precision nền).

## 4. Agent A — Generator (`scripts/gen_golden.py`)
Trách nhiệm: tạo dữ liệu, KHÔNG chấm điểm.
1. **5–6 base doc sạch** (hàm dựng trong code, không hardcode JSON tay cồng kềnh) phủ:
   mobile login, mobile feed/list, mobile form, web landing, web table/dashboard, ios safe-area.
   Mỗi base: vài element role khác nhau (button/text/image/icon/input), bbox hợp lệ trong viewport,
   style đủ field (font_size, color, bg_color, contrast_ratio…), không lỗi → rule engine ra 0 issue.
   **Tự kiểm:** chạy `run_rule_engine(base)` ra rỗng; nếu không, sửa base cho sạch.
2. **Mutator library** — 1 hàm/rule, mỗi hàm: `(clean_doc) -> (mutated_doc, expected_labels)`.
   Chế dữ liệu **vượt ngưỡng F0.4 vừa đủ** để đúng rule kêu (vd touch_target < 44dp → R1-CMP01;
   contrast < ngưỡng → R2; aspect lệch > ngưỡng → R3-IMG02; text="{{user_name}}" → R4-CNT…).
   Phủ **toàn bộ 32 rule** ở §1 (tối thiểu 1 case/rule). Đặt `element` đúng id bị mutate.
3. **Negative:** mỗi base → 1 case `kind=negative` (bản sạch). Cộng vài "near-miss" sạch
   (vd touch target = 46dp, ngay trên ngưỡng) để bắt FP biên.
4. Ghi `base/`, `cases/`, `labels/`. Idempotent (chạy lại ghi đè sạch). In số case sinh ra.
5. CLI: `python scripts/gen_golden.py [--out data/golden/schema]`.

**Không làm:** không gọi agent/LLM, không OCR, không đọc ảnh. Thuần dựng JSON.

## 5. Agent B — Scoring (`scripts/score_golden.py` + `tests/integration/test_golden.py`)
Trách nhiệm: chấm điểm, KHÔNG sinh dữ liệu (đọc cái A tạo).
1. Load mọi cặp `cases/<id>.json` + `labels/<id>.json`.
2. **Rule-only (mặc định):** `doc = CanonicalDoc.model_validate(case); out = run_rule_engine(doc)`
   → lấy `out.candidate_issues`.
3. **Matching:** 1 expected là **TP** nếu tồn tại candidate cùng `rule` AND cùng `element`
   (element=null thì khớp issue cấp screen) AND severity nằm trong `severity_range`.
   - expected không match → **FN**.
   - candidate không khớp expected nào (kể cả mọi candidate trong case negative) → **FP**.
4. **Metrics:** precision/recall/F1 **per-rule** và **tổng (micro)**. In bảng console + ghi
   `data/golden/report.md` (markdown bảng). Liệt kê FP/FN cụ thể (case_id, rule, element) để debug.
5. **`--with-agent` (tùy chọn, KHÔNG mặc định):** thay `run_rule_engine` bằng full reasoning
   **qua backend abstraction** — gọi `run_pipeline(..., run_agents=True)` HOẶC `run_review(doc)`
   (tùy cái nào nhận `CanonicalDoc` gọn hơn; ưu tiên `run_review` vì golden case đã là doc sẵn,
   không cần ảnh). Backend lấy theo env `AGENT_BACKEND` (codex máy này / cline prod).
   **KHÔNG import codex_client.** Nếu backend lỗi → in cảnh báo, vẫn xuất phần rule-only.
6. CLI: `python scripts/score_golden.py [--golden data/golden/schema] [--with-agent] [--rule R1-CMP01]`.
7. **pytest** `tests/integration/test_golden.py`: chạy rule-only trên golden, assert
   `recall_overall >= BASELINE` và `precision_overall >= BASELINE` (đặt baseline thoáng lúc đầu,
   vd 0.8/0.8, ghi rõ TODO siết sau). Mark `@pytest.mark.integration` nếu repo có pattern đó.

**Không làm:** không sửa rule engine để "đẹp số"; nếu rule sai thì ghi vào report, để người chốt.

## 6. Tích hợp (do session chính làm sau khi 2 agent xong)
1. `python scripts/gen_golden.py` → kiểm số case, vài file mẫu.
2. `python scripts/score_golden.py` → đọc `report.md`, soi FP/FN.
3. `pytest tests/integration/test_golden.py` + chạy full `pytest` (đảm bảo 111 cũ vẫn xanh).
4. Commit + push. Cập nhật CLAUDE.md mục 7 (đánh dấu golden set [x]).
