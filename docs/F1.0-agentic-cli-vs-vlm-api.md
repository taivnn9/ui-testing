## Điểm tích hợp hiện tại (code thật)
- `src/ui_defect/agents/llm_client.py::call_llm()` — **single-shot**, gửi `image + text → JSON`
  tới llama.cpp OpenAI-compatible. Không tool_use (đúng chốt CLAUDE.md mục 6).
- `src/ui_defect/agents/runner.py` — điều phối G0–G6, **mỗi agent một call cố định** (~7 call/ảnh).
- Pipeline cố định: Rule Engine (R1–R4) → VLM (G1–G6) → critic → aggregate.

## Verdict ngắn
Khả thi và *lý thuyết* chính xác hơn, **nhưng KHÔNG thay cả pipeline**. Dùng agentic như một
**tầng reasoning/verify có tool-use**, và **chỉ cho tập candidate khó** (kiểm soát cost/latency).

## Agentic hơn single-shot ở đâu (lợi thật)
Sức mạnh đến từ **vòng lặp tool-use + multi-turn**, không phải "model thông minh hơn":
1. **Zoom/crop on-demand** — nghi overlap `e12` → tự crop, nhìn lại pixel rồi mới kết luận →
   giảm false-positive (nguyên tắc #4: precision trên hết).
2. **Gọi rule engine on-demand** — hỏi lại "contrast `e7`?" → chạy R2 → số chính xác
   (giữ tách tất định/phán đoán, nguyên tắc #3, nhưng linh hoạt).
3. **Self-critique lặp thật** thay vì 1 pass cố định.
4. **Skill/rule tái dùng** — few-shot + heuristic dạng file.

## 5 caveat phải cân
1. **VISION — quan trọng nhất.** Dự án vision-only (nguyên tắc #1, bắt buộc pixel). Agentic chỉ
   có giá trị nếu đẩy được ảnh/crop xuống model **mỗi turn**. Cline là coding agent, vision tùy
   provider, không first-class → nếu không gửi được pixel trong loop thì **thua** `call_llm` hiện tại.
2. **Mâu thuẫn self-host hiện tại.** CLAUDE.md chốt "llama.cpp — không tool_use". Agentic = bắt
   buộc tool-use → cần model **vừa vision vừa tool_use tốt** (gemma/llama.cpp yếu khoản này) →
   quyết định lớn về hạ tầng (hosted VLM, hoặc Qwen2.5-VL + harness tool-use).
3. **JSON structured output kém ổn định** khi agent đi lang thang → cần bước cuối "emit JSON"
   khóa schema mục 5.
4. **Latency × cost nhân lên.** Hiện ~7 call cố định/ảnh; agentic = N call/agent không đoán trước
   → phình p95 + cost. ⇒ **chỉ chạy agentic cho candidate khó**.
5. **Reproducibility.** Fixed-pipeline dễ regression-test trên Golden Set (việc còn dang dở);
   agentic loop không tất định → đo precision/recall + tune ngưỡng khó hơn.

## Đề xuất kiến trúc: HYBRID
```
Rule Engine (R1–R4) → candidate_issues
   ├─ candidate "dễ/chắc"  → VLM single-shot (call_llm hiện tại)   # giữ nguyên: rẻ, ổn định, test được
   └─ candidate "khó/mơ hồ" → AGENTIC critic (tool-use: crop/zoom/re-run rule + self-critique)
                                   → bước "emit JSON" khóa schema
```
- Giữ rule engine + pipeline cố định làm **backbone** (precision cao phần tính được, test trên Golden Set).
- Agentic **chỉ ở tầng critic/verify** cho subset lọc (confidence giữa, hoặc lỗi cần thẩm mỹ/ngữ cảnh).

## Tooling: Cline có tối ưu không?
Cline headless gượng (extension VS Code, vision không chắc, khó nhúng request path).

| Phương án | Ưu | Nhược |
|---|---|---|
| Cline headless | Đã có sẵn | Headless gượng, vision không chắc, khó nhúng API service |
| Claude Code headless `claude -p --output-format json` | tool-use + vision + JSON first-class, script hóa dễ | hosted, tốn token |
| **Agent SDK loop tự build** (SDK + tool `crop_region`/`get_contrast`/`run_rule`) | kiểm soát hoàn toàn, nhúng thẳng Python sẵn có, chọn model tùy | tự viết loop ~150–200 dòng |

**Khuyến nghị:** với API service production, **không** shell-out Cline trong request path. Build
**agentic critic ngay trong Python** (Agent SDK loop) tái dùng analyzer/rule sẵn có. Cline để
**dev/thử nghiệm offline trên Golden Set** thì hợp.
