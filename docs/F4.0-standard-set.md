# F4.0 — Bộ chuẩn `standard_v1` + đo Precision/Recall (kiểm thử đột biến UI)

> **TL;DR:** Tập dữ liệu có nhãn lỗi sẵn để đo precision/recall và tune ngưỡng (F0.4). Tạo nhanh bằng **mutation testing**: inject lỗi đã biết → tập positive + giữ bản sạch làm negative. Core scoring là **rule-only, deterministic, backend-agnostic**.
>
> Spec sống. Chốt 2026-06-04.

## 0. Ràng buộc nền (QUAN TRỌNG)
- **Backend-agnostic — phải chạy với Cline.** Triển khai thật dùng **Cline** (máy công ty); Codex chỉ là backend test máy này. Vì vậy:
  - **Core standard + scoring = rule-only, deterministic, không đụng agent backend nào.** `run_rule_engine(doc)` thuần tính toán → kết quả như nhau bất kể Cline/Codex/none. Đây là phần tune ngưỡng F0.4.
  - Đường reasoning (tùy chọn) đi **qua abstraction** `AGENT_BACKEND` (`agents/backends.py: run_backend` / `agents/runner.py: run_review`). **TUYỆT ĐỐI không import `codex_client` trực tiếp** trong script standard. Cờ CLI là **`--with-agent`** (không phải `--with-codex`).
- **Tier 1 trước (schema-level).** Tier 2 (ảnh thật Playwright) chỉ tạo dir + TODO, chưa build (OCR local chưa set up).

## 1. Catalog rule đích (32 rule tất định)
Standard label bám đúng các `rule` ID rule engine phát ra:
- **R1 geometry:** `R1-CMP01` (touch target), `R1-CMP16` (tap gap), `R1-ENV01/02/03` (safe-area), `R1-LAY01` (overlap siblings), `R1-LAY02` (offscreen), `R1-LAY03` (overflow container), `R1-LAY04` (lệch grid), `R1-LAY14` (near-dup position).
- **R2 color:** `R2-STY01..05`, `R2-STY13` (contrast / opacity / dark-mode).
- **R3 image:** `R3-IMG02` (méo aspect), `R3-IMG03`, `R3-IMG07`, `R3-IMG08`, `R3-IMG09` (scale-mode), `R3-IMG12`.
- **R4 text:** `R4-CNT01/02/04/05/06/07/08` (placeholder/undefined/i18n key/lorem/escape/mojibake/stacktrace/debug…), `R4-STATE03`, `R4-TYP03` (font nhỏ), `R4-TYP05` (truncation).

> Mỗi mutator nhắm 1 rule trong danh sách. Agent A đọc trực tiếp `src/ui_defect/rules/*.py` để biết điều kiện kích hoạt + ngưỡng (F0.4) và chế dữ liệu vượt ngưỡng vừa đủ.

## 2. Layout thư mục
```
data/standard_v1/
  schema/                 # Tier 1 — làm ngay
    base/    <base>.json      # CanonicalDoc SẠCH (nguồn để mutate)
    cases/   <case_id>.json   # CanonicalDoc đã mutate (INPUT cho rule engine)
    labels/  <case_id>.json   # ground truth (kỳ vọng)
  images/                 # Tier 2 — chỉ dir + README TODO, chưa build
  report.md               # output của score (Agent B sinh)
scripts/
  gen_standard.py           # Agent A: base → cases + labels
  score_standard.py         # Agent B: chấm điểm
tests/integration/
  test_standard.py          # Agent B: pytest baseline
```

## 3. Hợp đồng dữ liệu (interface 2 agent — KHÓA CHẶT)
2 agent chạy song song nhờ thống nhất 2 schema sau. Không đổi field name nếu chưa báo.

**3.1. `cases/<case_id>.json`** — đúng một `CanonicalDoc` (Pydantic v2, `src/ui_defect/schema/models.py`, F0.2) đã mutate, serialize `model_dump(mode="json", exclude_none=True)`. Phải load lại được bằng `CanonicalDoc.model_validate(json.load(...))`.

**3.2. `labels/<case_id>.json`**
```jsonc
{
  "case_id": "cmp01_tiny_button_v1",   // == tên file (không .json)
  "base": "mobile_login",              // base doc gốc
  "mutation": "shrink_touch_target",   // tên mutator
  "kind": "positive",                  // "positive" | "negative"
  "expected": [                        // [] BẮT BUỘC khi kind=negative
    {
      "rule": "R1-CMP01",
      "element": "e7",                 // null nếu lỗi cấp screen
      "severity_range": { "min": "medium", "max": "high" }
    }
  ]
}
```
- **positive:** sau mutate, rule trong `expected` PHẢI fire trên đúng element.
- **negative:** base sạch (hoặc biến thể vẫn hợp lệ) — rule engine fire bất kỳ issue nào = **FP**.
- Mỗi base sạch cũng xuất thành 1 case `kind=negative` (đo precision nền).

## 4. Agent A — Generator (`scripts/gen_standard.py`)
Tạo dữ liệu, KHÔNG chấm điểm.
1. **5–6 base doc sạch** (dựng trong code) phủ: mobile login, mobile feed/list, mobile form, web landing, web table/dashboard, ios safe-area. Mỗi base: vài role khác nhau, bbox hợp lệ, style đủ field, không lỗi → rule engine ra 0 issue. **Tự kiểm:** `run_rule_engine(base)` ra rỗng.
2. **Mutator library** — 1 hàm/rule: `(clean_doc) -> (mutated_doc, expected_labels)`. Chế dữ liệu vượt ngưỡng F0.4 vừa đủ (vd touch_target < 44dp → R1-CMP01; contrast < ngưỡng → R2; aspect lệch > ngưỡng → R3-IMG02; `text="{{user_name}}"` → R4-CNT…). Phủ **toàn bộ 32 rule** (tối thiểu 1 case/rule). Đặt `element` đúng id bị mutate.
3. **Negative:** mỗi base → 1 case `kind=negative`. Cộng vài "near-miss" sạch (vd touch target = 46dp, ngay trên ngưỡng) để bắt FP biên.
4. Ghi `base/`, `cases/`, `labels/`. Idempotent. In số case.
5. CLI: `python scripts/gen_standard.py [--out data/standard_v1/schema]`.

**Không làm:** không gọi agent/LLM, không OCR, không đọc ảnh. Thuần dựng JSON.

## 5. Agent B — Scoring (`scripts/score_standard.py` + `tests/integration/test_standard.py`)
Chấm điểm, KHÔNG sinh dữ liệu.
1. Load mọi cặp `cases/<id>.json` + `labels/<id>.json`.
2. **Rule-only (mặc định):** `doc = CanonicalDoc.model_validate(case); out = run_rule_engine(doc)` → lấy `out.candidate_issues`.
3. **Matching:** 1 expected là **TP** nếu có candidate cùng `rule` AND cùng `element` (element=null khớp issue cấp screen) AND severity trong `severity_range`.
   - expected không match → **FN**.
   - candidate không khớp expected nào (kể cả trong case negative) → **FP**.
4. **Metrics:** precision/recall/F1 per-rule và tổng (micro). In bảng console + ghi `data/standard_v1/report.md`. Liệt kê FP/FN cụ thể (case_id, rule, element).
5. **`--with-agent` (tùy chọn):** thay `run_rule_engine` bằng full reasoning **qua backend abstraction** — gọi `run_pipeline(..., run_agents=True)` HOẶC `run_review(doc)` (ưu tiên `run_review` vì standard case đã là doc sẵn). Backend lấy theo env `AGENT_BACKEND` (codex máy này / cline prod). **Không import codex_client.** Backend lỗi → cảnh báo, vẫn xuất phần rule-only.
6. CLI: `python scripts/score_standard.py [--standard data/standard_v1/schema] [--with-agent] [--rule R1-CMP01]`.
7. **pytest** `test_standard.py`: rule-only trên standard, assert `recall_overall >= BASELINE` và `precision_overall >= BASELINE` (baseline thoáng lúc đầu, vd 0.8/0.8, TODO siết sau). Mark `@pytest.mark.integration` nếu repo có pattern.

**Không làm:** không sửa rule engine để "đẹp số"; rule sai thì ghi vào report.

## 6. Tích hợp (session chính làm sau khi 2 agent xong)
1. `python scripts/gen_standard.py` → kiểm số case.
2. `python scripts/score_standard.py` → đọc `report.md`, soi FP/FN.
3. `pytest tests/integration/test_standard.py` + full `pytest` (đảm bảo 111 cũ vẫn xanh).
